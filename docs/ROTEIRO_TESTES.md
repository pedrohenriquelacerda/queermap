# Roteiro de testes dos fluxos principais

Roteiro para a rodada de testes no **ambiente publicado** (Render + Neon), feita **em computador e em celular**. Cada passo tem um resultado esperado; o que fugir dele vira uma issue (modelo em `.github/ISSUE_TEMPLATE/bug.md`).

> Os nomes de botões e menus abaixo foram conferidos nas telas do código. Os resultados esperados descrevem o que o código faz hoje, inclusive o que **não** é feito (veja "O que o app não faz hoje" no fim).

## Antes de começar

- Use só dados fictícios. Não cadastre dados reais da ONG nem de pessoas.
- Anote o endereço testado, o commit publicado (veja `/health` e o painel do Render) e a data.
- Plano gratuito do Render: o primeiro acesso pode demorar até cerca de 1 minuto (o servidor "acorda"). Isso não é bug; só registre se passar muito disso.
- Para repetir em computador **e** celular, use a tabela de registro no fim. Uma execução = uma coluna.
- Contas de teste do painel: uma de **Administração** e uma de **Edição**, ambas com 2FA. Quem cria as contas e guarda as senhas é a pessoa responsável pela rodada; elas não ficam neste arquivo.
- O passo B6 (Métricas) só vale se o PR das métricas já estiver publicado. Se não estiver, marque "n/a".

## O que o app não faz hoje (não é bug do roteiro)

Conferido no código. Se a ONG quiser que isso passe a existir, vira uma melhoria, não uma falha desta rodada:

- **Senha errada no login não entra no histórico.** Só o código de 2FA errado (`sessao.falha_2fa`) é registrado. A senha errada só é contida pelo limite de tentativas.
- **Acesso negado (403) não entra no histórico.** Edição tentando abrir uma área de Administração recebe o erro, mas nada é registrado.
- **Envio não vira local sozinho, mas há atalho.** Tratar um envio é mudar a situação (Novo, Em análise, Resolvido, Arquivado) e anotar. Em sugestões, **Criar local a partir desta sugestão** abre o formulário já preenchido; a pessoa revisa e salva como rascunho.
- **A leitura de um envio é registrada**: abrir um envio novo gera "Abriu um envio pela primeira vez" no histórico.
- **Contas criadas pelo comando `npm run admin:criar` aparecem no histórico como feitas por "Conta removida"**, porque não há pessoa logada. É só o nome mostrado, mas pode confundir quem lê o histórico.
